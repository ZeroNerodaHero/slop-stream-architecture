what this is. how to run it. how to change it.

what it is

a test stream site. one computer. you open its ip. one person go live. other people watch. there is chat beside the video. there are accounts, but nobody has to have one.

streamer
the computer
watchers

the streamer upload once. the computer copy it to every watcher. that is the one trick everything else sits on.

run it

on the server:

git clone <repo> && cd slop-stream-architecture
./scripts/deploy.sh
  1. it check the box. ports 80 and 443 must be free.
  2. it write .env. your ip goes in.
  3. it pull the images. nothing is compiled here.
  4. it start twelve boxes. see boxes.
  5. it print a url. open it. click through the warning.

the warning is the https cert. it is self made, for your ip. camera only works on https. the warning is enough.

nothing is compiled on the server. every push to main makes github build the four images. deploy pull them. a 1 GB box is enough. the build takes a few minutes after a push. a deploy before it is done says so and does nothing.

update it

you typewhat happens
./scripts/deploy.sh --pullpull the repo. then the images for it. new knobs land in .env with defaults.
./scripts/deploy.sh apionly the api. streams stay up.
./scripts/deploy.sh frontendonly the pages. streams stay up.
./scripts/deploy.sh videoends every stream. it warns first.
./scripts/deploy.sheverything again.
./scripts/deploy.sh --prune-deploydisk full of old builds. drop them. then deploy.

build it yourself

./scripts/deploy.sh --build compiles on the machine it runs on. an hour and 4 GB of ram on a small box. a few minutes on a laptop.

changes not pushed yet, but you want them on the box:

./scripts/ship.sh --to gcloud:test-machine   # laptop: build, send over ssh, print a tag
./scripts/deploy.sh --images <that tag>      # box: start them. pull nothing

--to billy@1.2.3.4 for any other box.

work on the pages

cd frontend && npm install && npm run dev

open http://localhost:42069. edits show up live. the camera works there too.

which backend it talks to, in order: BACKEND=https://1.2.3.4 npm run dev, or that line in frontend/.env. else the docker stack on this machine.

these docs: SHOW_DOCS=1 in the repo's .env. then http://localhost:42069/tech-docs. only the dev server serves them. a deploy never does.

ports

  • 80 and 443, tcp. the site. http just sends you to https.
  • 7882, udp. the video packets. one port for all of them.
