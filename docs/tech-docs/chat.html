redis

you type. hello from the cave >

the line goes to the chat box. the chat box puts it in the memory box. the memory box keeps the last 500. the chat box sends the line to every socket in the room. all of it in one trip.

a new viewer gets the last 200 lines first. then the live ones.

a line carries the speaker's face and badges as they are now. a picture on a line: click it and it fills the page. escape closes it.

limits

  • 500 letters a line. 501 letters: refused
  • pictures on a line: ten at most. the page shrinks each one first. a login only.
  • 500 lines a room in memory. the oldest fall off.

how fast you may talk is a bucket of tokens. a line takes one. the bucket refills slowly. the send button counts down and shakes when it is empty.

why redis streams

every line gets an id. a viewer who drops and comes back says the last id it saw. it gets what it missed. no gap. no double.

one structure does the memory and the fan-out. not a list plus pub/sub, which can disagree. not kafka, which is a cluster for a problem this small.

the database is asked two things at hello only. is this socket really the streamer. who does its cookie say it is. the database down: you can still read. a say waits for it.

kept for good

CHAT_PERSIST=1 in .env, then a deploy of the api image. every line also goes to the database.

  • scroll past the last 500. the room asks for the page before.
  • search the room. the words as written. 50 hits at most, newest first. from:<name> narrows it.
  • jump to one line. the room opens around it.

off, search says history is not kept.

names and colours

  • a login is blue. a nick is red. the streamer is green.
  • a group's badge sits next to the name. a small box, the group's colour, a word in capitals.
  • the fake streams' chatters wear BOT. the robot button hides their lines.

where the panel sits

right of the video. or the left. or a window you drag around. a setting of this browser. the chat tab of the user modal shows a picture of each.

the chat button on the video closes it and opens it again.

if the chat box restarts

every socket gets a close. up to 2 s to leave. the panel comes back in 3 s. the last lines reload from memory. nothing is lost.
